# API Documentation

Meetdy uses Tauri's command/event IPC model for frontend-backend communication. Commands
are invoked from TypeScript via `invoke()` (or auto-generated Specta bindings) and events
are pushed from Rust via `app.emit()`.

## Contents

| Document | Description |
|---|---|
| [commands.md](./commands.md) | All Tauri commands grouped by domain |
| [events.md](./events.md) | All events emitted by the backend |
| [types.md](./types.md) | Key shared types and their schemas |

## Architecture

```
Frontend (React/TypeScript)          Backend (Rust)
─────────────────────────────        ─────────────────
invoke("command_name", args)  ──→    #[tauri::command] fn
                  ←──  Result<T, String>

listen("event_name", cb)      ←──    app.emit("event_name", payload)
```

- **Commands**: Request-response. Frontend calls, backend returns `Result<T, String>`.
- **Events**: Fire-and-forget from backend. Frontend subscribes with `listen()`.
- **Auto-generated bindings**: `src/bindings.ts` is generated by `tauri-specta` from the
  `#[specta::specta]` annotations on each command and type. Prefer these bindings over
  raw `invoke()` calls.

## Source Layout

Commands are defined in `src-tauri/src/commands/` and registered via the `.invoke_handler()`
builder in `src-tauri/src/lib.rs`.
